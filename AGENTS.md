# Agent Instructions

Before making changes to this repository, read `PORTFOLIO_CONTEXT.md` completely.

Treat it as the authoritative source for:
- public portfolio content
- professional positioning
- project descriptions
- confidentiality constraints
- implemented vs planned technologies
- portfolio goals and roadmap

## Working rules

- Inspect the existing code before editing.
- Preserve existing architecture and patterns unless the task requires a change.
- Do not invent facts, experience, metrics, or technologies.
- Never expose credentials, secrets, confidential employer information, customer information, or proprietary internal details.
- Do not present roadmap technologies as already implemented.
- Avoid unnecessary dependencies.
- Do not modify infrastructure, deployment, database configuration, or CI/CD unless explicitly requested.
- Do not weaken tests to make changes pass.
- Run relevant tests after implementation.
- Treat `main` as the production branch.
- Do not commit, push, merge, or deploy unless explicitly instructed.

For implementation work, prefer cohesive changes over tiny piecemeal edits.

For public-facing UI and content, prioritize clarity, evidence, accessibility, responsiveness, and the design direction defined in `PORTFOLIO_CONTEXT.md`.
